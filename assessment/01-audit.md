> **Document ID:** `ASSESSMENT-01`  
> **Target Platform:** Dual-Service AI Interview Platform (`api/` Ruby on Rails + `web/` React 18 / TypeScript)  
> **Evaluation Lens:** SDET Depth / Quality Engineering Bar  
> **Audit Date:** 2026-10-07  
> **Assessor:** Muhammad Nuril Huda Maulani

---

## 1. Executive Summary & Ship / Do-Not-Ship Decision

### The Decision: **BLOCKED (DO NOT SHIP)**

The platform in its current state contains **three critical P0 Blockers** and **multiple P1 Major defects** involving data integrity, broken core customer journeys, and frontend/backend contract disconnects. Shipping this version to a client or candidate today would result in immediate operational failure:

1. **Candidates cannot access the interview** from the invitation links generated by recruiters (P0).
2. **Assessor overrides and notes are silently destroyed** if a portfolio is ever regenerated (P0 Data Integrity).
3. **The platform has zero automated tests and zero CI validation gates**, allowing breaking regressions to merge undetected (P0 Workflow / Safety).
4. **Fit/Gap analysis reports render blank required skill levels** on the recruiter dashboard due to an unaligned data contract (P1).

### The Ship Line (Gate Preconditions)
Before this platform can be considered **Releasable (Ship)**:
* All **P0 Blockers** must be resolved with regression checks in place.
* The API/Web contract for Fit/Gap reporting and invite routing must be harmonized.
* A mandatory CI workflow gate must enforce the Definition of Ready and automated tests.

## 2. Systemic Patterns Behind the Defects

Rather than viewing these bugs as isolated oversights, our code analysis reveals three clear **systemic architectural patterns**:

### Pattern A: "The Seam Vacuum" (Frontend vs. Backend Contract Drift)
* Both services were built with isolated assumptions about each other's domain:
  * Backend models assume `APP_BASE_URL` is the origin for user navigation (`Session#invite_url` points to port 3001), ignoring the fact that the frontend SPA runs on port 5173.
  * Backend returns `expected_level`, while frontend components and TypeScript models look for `required_level`.
  * Frontend sends nested attributes for deletion expecting array slicing to work, while Rails ActiveRecord requires explicit `_destroy: true`.
* **Root Cause:** Absence of end-to-end integration contracts or schema verification between `api/` and `web/`.

### Pattern B: Destructive Regeneration Cascades
* Regeneration routines (`save_skills` in `Portfolios::Generator` and `regenerate_stale_fitgap_reports` in `PortfolioSkillsController`) rely on `destroy_all` cascades to achieve idempotency, without guarding child associations (`assessor_overrides`).
* **Root Cause:** Treating human inputs as transient downstream artifacts rather than protected system-of-record entities.

### Pattern C: Ghost Specifications & Missing Gates
* Features such as User Sign-up and Language Selection exist partially in the frontend codebase without corresponding backend routes or consistent edit persistence.
* **Root Cause:** Lack of a Definition of Ready (DoR) gate that prevents code from being written without a frozen spec and contract tests.

## 3. Severity-Ranked Risk Register

All findings are categorized using the platform standard severity scale:
* **P0 Blocker**: Objective cannot be achieved at all; no workaround; main function broken.
* **P1 Major**: Works superficially but data or logic is wrong underneath, or data-integrity issue, or reachable only via manual workaround.
* **P2 Minor**: Works and data is correct, but limited non-blocking issue.
* **P3 Cosmetic**: Purely visual or copy defect; no functional/data impact.

### [P0-01] Broken Candidate Invite URL (404 Routing Failure)
* **Severity:** **P0 Blocker**
* **Classification:** **Built Wrong**
* **Impact:** Candidates who click the invite link sent by recruiters land on a Rails 404 error page. The core interview function cannot be reached.
* **Location:** `api/app/models/session.rb` (lines 28–31), `web/src/pages/assessments/AssessmentInvitePage.tsx`.
* **Evidence / Repro Steps:**
  1. Recruiter creates an assessment and invites a candidate via `POST /api/v1/assessments/:id/sessions`.
  2. The API generates `invite_url`: `#{ENV['APP_BASE_URL'] || 'http://localhost:3001'}/interview/#{invite_token}`.
  3. Recruiter copies this link from `AssessmentInvitePage.tsx` and sends it to the candidate.
  4. Candidate visits `http://localhost:3001/interview/:token`.
  5. **Failure:** Rails backend on port 3001 has no route for `GET /interview/:token` (that route belongs to Vite/React on port 5173). Rails responds with `ActionController::RoutingError (No route matches [GET] "/interview/...")`.
* **Remediation Plan:** Update `Session#invite_url` to read a dedicated `FRONTEND_BASE_URL` (defaulting to `http://localhost:5173`), or have the frontend construct the link using its current window origin.

### [P0-02] Silent Destruction of Human Assessor Overrides on Portfolio Regeneration
* **Severity:** **P0 Blocker / Data Integrity**
* **Classification:** **Built Wrong**
* **Impact:** Any manual grade adjustment, notes, or expert evaluation written by an assessor is permanently deleted if the portfolio is regenerated.
* **Location:** `api/app/services/portfolios/generator.rb` (line 154: `portfolio.portfolio_skills.destroy_all`), `api/app/models/portfolio_skill.rb` (`has_one :assessor_override, dependent: :destroy`).
* **Evidence / Repro Steps:**
  1. Complete an interview and generate a portfolio.
  2. Assessor overrides a skill (e.g. adjusts Level from L2 to L3 with detailed notes) via `POST /api/v1/portfolio_skills/:id/override`.
  3. Assessor or system triggers portfolio regeneration via `POST /api/v1/sessions/:id/portfolio/regenerate`.
  4. Background worker executes `Portfolios::Generator#save_skills`, which calls `portfolio.portfolio_skills.destroy_all`.
  5. **Failure:** Due to foreign key cascades, `assessor_overrides` rows referencing those skills are permanently deleted. The new AI-generated skills have no memory of previous human assessments.
* **Remediation Plan:** Preserve existing overrides across regeneration by updating existing `portfolio_skills` in place or snapshotting overrides before replacing AI ratings.

### [P0-03] Absence of Automated Test Suites & CI Workflow Enforcement
* **Severity:** **P0 Blocker / Safety**
* **Classification:** **Missing Inputs / Workflow Risk**
* **Impact:** Code changes can be committed and merged with zero verification. Regressions on critical paths cannot be caught before deployment.
* **Location:** Repo root (missing `.github/workflows/`), `api/` (missing `spec/` tests despite `.rspec` and `rspec-rails` in Gemfile), `web/` (missing test script and framework).
* **Evidence / Repro Steps:**
  1. Inspect root directory: no CI pipeline configuration exists.
  2. Inspect `api/`: `spec/` directory does not exist.
  3. Inspect `web/package.json`: only `dev`, `build`, `preview` scripts exist; no test runner installed.
* **Remediation Plan:** Implement a dual-layer CI workflow:
  1. PR Workflow Gate validating Definition of Ready (DoR) compliance.
  2. Automated test suite for backend API integrity and frontend integration.

### [P1-01] Contract Mismatch: Blank "Required Level" Column in Fit/Gap Report
* **Severity:** **P1 Major**
* **Classification:** **Built Wrong (API/Web Contract Mismatch)**
* **Impact:** The Fit/Gap analysis report renders the "Required" level column as empty (`—`), depriving assessors of visual benchmark comparisons.
* **Location:** `api/app/services/fit_gap/engine.rb` (line 62) vs `web/src/components/fitgap/ComparisonTable.tsx` (line 50) and `web/src/types/index.ts` (line 132).
* **Evidence / Repro Steps:**
  1. Generate a Fit/Gap report for any candidate against a vacancy.
  2. Backend returns `skill_comparisons` array with `{ "expected_level": 3, "candidate_level": 3, ... }`.
  3. Frontend `ComparisonTable.tsx` reads `LEVEL_LABELS[c.required_level]`.
  4. **Failure:** `c.required_level` is `undefined`. Table displays blank in the Required column.
* **Remediation Plan:** Update backend `FitGap::Engine` to emit both `expected_level` and `required_level` (or standardize on `expected_level` in frontend component and type definition).

### [P1-02] Omission of `is_override` Flag in Fit/Gap Comparisons
* **Severity:** **P1 Major**
* **Classification:** **Built Wrong**
* **Impact:** The recruiter dashboard never displays the pencil icon (`✏`) indicating human override in the Fit/Gap comparison table, obscuring assessor intervention.
* **Location:** `api/app/services/fit_gap/engine.rb` (lines 58–67) vs `web/src/components/fitgap/ComparisonTable.tsx` (line 56).
* **Evidence / Repro Steps:**
  1. An assessor overrides a skill rating.
  2. `FitGapReport` is regenerated.
  3. Frontend expects `c.is_override: true` to render `<span ...>✏</span>`.
  4. Backend comparison hash omits `is_override`.
* **Remediation Plan:** Include `is_override: portfolio_skill&.dig(:overridden) || false` in the comparison hash.

### [P1-03] "Zombie Skills" on Vacancy & Assessment Edit
* **Severity:** **P1 Major / Data Integrity**
* **Classification:** **Built Wrong**
* **Impact:** Skills removed by the user in the Vacancy/Assessment Edit forms remain stored in the database and reappear upon page reload.
* **Location:** `web/src/pages/vacancies/VacancyEditPage.tsx` (lines 49, 78) & `web/src/pages/assessments/AssessmentEditPage.tsx` vs Rails `accepts_nested_attributes_for`.
* **Evidence / Repro Steps:**
  1. Edit an existing Vacancy that has 3 skills.
  2. Click the `X` button on skill #2. The skill disappears from the browser UI.
  3. Click "Save Changes". The frontend sends `vacancy_skills_attributes: [skill1, skill3]`.
  4. Rails updates skill1 and skill3, but does NOT delete skill2 because no `_destroy: true` flag with ID was sent.
  5. Reload the page: skill #2 reappears.
* **Remediation Plan:** Track deleted skill IDs in the frontend form and append `{ id: skillId, _destroy: true }` upon submission.

### [P1-04] Lost Language Configuration on Assessment Edit
* **Severity:** **P1 Major**
* **Classification:** **Missing Spec / UI Regression**
* **Impact:** An assessment configured in Indonesian (`id`) silently loses its language field or cannot be reviewed/updated in the edit form, causing the AI prompt compiler to default to English.
* **Location:** `web/src/pages/assessments/AssessmentEditPage.tsx` (lines 40, 52, 77–81).
* **Evidence / Repro Steps:**
  1. Create an Assessment with language set to Indonesian (`id`).
  2. Navigate to `/assessments/:id/edit`.
  3. The edit form lacks a Language selector; `form.reset` omits language.
  4. Saving the form submits without language, triggering system prompt recompilation that risks reverting interview language.
* **Remediation Plan:** Include `language` in `AssessmentEditPage` form fields, reset values, and update payload.

### [P1-05] Orphaned Signup Flow & Missing API Endpoint
* **Severity:** **P1 Major / Dead Code**
* **Classification:** **Missing Spec / Built Wrong**
* **Impact:** Users attempting to register or developers reviewing auth encounter non-functional dead code.
* **Location:** `web/src/pages/auth/SignupPage.tsx`, `web/src/services/auth.ts` (line 17: `api.post("/signup")`), `api/config/routes.rb`.
* **Evidence / Repro Steps:**
  1. `SignupPage.tsx` exists and renders a full registration form.
  2. It submits to `POST /api/v1/signup`.
  3. Backend has no `/signup` route, only `POST /api/v1/auth/login`.
  4. Furthermore, `App.tsx` does not define a `/signup` route.
* **Remediation Plan:** Clarify product specification: either implement backend registration with tenant assignment, or remove orphaned signup UI to prevent user confusion.

### [P2-01] Documentation vs. Initializer Environment Variable Conflict
* **Severity:** **P2 Minor**
* **Classification:** **Built Wrong (Documentation Drift)**
* **Impact:** Developers and DevOps following `api/README.md` will experience a server crash in production due to an uninitialized variable.
* **Location:** `api/README.md` (`GEMINI_ANALYSIS_MODEL`) vs `api/config/initializers/gemini.rb` (line 7: `GEMINI_FLASH_MODEL`).
* **Evidence / Repro Steps:**
  1. Setup `.env` using README instructions (`GEMINI_ANALYSIS_MODEL=...`).
  2. Boot Rails in production environment (`RAILS_ENV=production rails s`).
  3. Initializer raises `RuntimeError: Missing required Gemini environment variables: GEMINI_FLASH_MODEL`.
* **Remediation Plan:** Align README and `.sample` configuration with `GEMINI_FLASH_MODEL`.

---

### [P2-02] Misleading HTTP Method Naming in Frontend API Client
* **Severity:** **P2 Minor**
* **Classification:** **Built Wrong (Code Quality)**
* **Impact:** Developers reading `portfoliosApi.getOverride` assume an idempotent GET request, but it triggers a state-mutating POST request.
* **Location:** `web/src/services/portfolios.ts` (line 5: `getOverride: (portfolioSkillId, data) => api.post(...)`).
* **Remediation Plan:** Rename `getOverride` to `saveOverride` or `overrideSkill`.
